# Build SPV (Spatial Viewer) — a static, browser-based 3D spatial transcriptomics viewer (`.h5ad` → GitHub Pages)

## 1. Goal

Build **SPV**, a lightweight, client-side-only web app that loads **one AnnData `.h5ad` file at a time** and renders its cells/spots as an interactive **3D point cloud**, colored by cell metadata (`obs`) or by gene expression (`X`). It must run entirely in the browser with no backend, deploy as a GitHub Pages site (`https://<user>.github.io/<repo>/`), and stay smooth with several hundred thousand points.

The input files are **Squidpy-compatible AnnData objects** (produced with Scanpy/Squidpy from Visium, MERFISH/Vizgen, Xenium, CosMx, seqFISH, Stereo-seq, etc.). Squidpy's storage conventions (§5.2, §5.6) are the primary contract: `obsm["spatial"]` / `obsm["spatial3d"]` for coordinates, `uns["spatial"][library_id]` for images and scale factors, `obsp["spatial_connectivities"]` for the spatial graph, and a `library_key` column in `obs` for multi-section datasets. Generic AnnData files must still work, but Squidpy layouts get first-class treatment.

**The primary use case is multi-section 2D data**: several tissue sections (Visium slides, Xenium/CosMx slides, serial sections) concatenated into one AnnData with 2D `obsm["spatial"]`, a section identifier in `obs`, and — for Visium-style data — one entry per section in `uns["spatial"]` with a tissue image and scale factors. The viewer's core job is to turn that into an explorable 3D stack: sections spread along z, each optionally drawn on top of its tissue image, steppable one at a time, or tiled side-by-side for comparison. Native 3D coordinates (`spatial3d`, MERFISH-style) are the secondary case and must also work.

Users choose a dataset from (a) a curated list hosted alongside the site, (b) an arbitrary URL, or (c) a local file on their machine that never leaves the browser.

**Naming.** The system is called **SPV**, short for **Spatial Viewer** — use exactly that capitalization everywhere a user sees it: the `<title>` ("SPV — Spatial Viewer"), the top-bar wordmark (plain styled text "SPV", with "Spatial Viewer" as a subtitle or tooltip, no external logo assets), the Help modal, screenshot filenames (`spv-<dataset>-<timestamp>.png`), and the README title ("SPV — Spatial Viewer"). Use `spv` in machine-facing identifiers: `package.json` name, the CSS class prefix (`spv-`), the URL-state version key, and the debug object (`window.__spv`). Write the expansion as two words, "Spatial Viewer", never "SpatialViewer" or "spatial-viewer" in prose.

## 2. Non-negotiable constraints

- **100% static.** No server, no API, no build-time data conversion required for hosted datasets. Everything (HDF5 parsing, rendering, state) happens in the browser.
- **One dataset at a time.** Switching datasets fully tears down the previous one (GPU buffers, worker state, virtual filesystem entries) before loading the next.
- **Lightweight.** Vanilla TypeScript + Vite, Three.js, h5wasm. No React/Vue/Svelte, no UI component library, no d3 (write small colormap lookup tables yourself), no state-management library. Initial JS payload under ~400 KB gzipped, excluding the h5wasm `.wasm` binary, which is loaded lazily the first time a dataset is opened (with a progress indicator).
- **GitHub Pages cannot set custom HTTP headers.** Do not depend on COOP/COEP, `SharedArrayBuffer`, or service-worker header tricks. Use plain Web Workers with `postMessage` and transferable `ArrayBuffer`s.
- **Never guess library APIs.** Before writing code against h5wasm or Three.js, read their README and `.d.ts` files in `node_modules`, and check the currently published npm versions before pinning. APIs in both libraries have changed across versions.
- **Privacy.** Local files are read via the File API into the h5wasm virtual filesystem only. Nothing is uploaded anywhere. Say so in the UI.

## 3. Stack (verify current versions, then pin exact versions in `package.json`)

|---|---|---|

- **Open URL** text field (must support CORS; show a clear error if the fetch is blocked).
- **Open local file**: `<input type="file" accept=".h5ad,.h5">` plus drag-and-drop anywhere on the page.
- **Deep link**: `#dataset=<id>` or `#url=<encoded-url>` in the URL hash auto-loads on page open (see §8).

### 4.3 Loading strategy
- Remote: check whether h5wasm's lazy-file / HTTP `Range` request helper works against the host (GitHub Pages supports `Range`). If it does, use it so only the bytes HDF5 actually touches are downloaded; otherwise fall back to a full `fetch` with byte-level progress, written into the worker's in-memory filesystem.
- Local: inside the worker, check whether the h5wasm build exposes Emscripten `WORKERFS`. If so, mount the `File` object directly so the browser reads only the requested byte ranges instead of copying the whole file into memory. Otherwise read into an `ArrayBuffer` and write it to MEMFS.
- Show estimated memory use before loading files over ~500 MB and warn above ~1.5 GB (browser tab limits vary).

## 5. Reading `.h5ad` (AnnData on-disk format) — the riskiest part, implement carefully

Implement `src/h5ad/` as a schema-aware reader on top of h5wasm that runs inside a Web Worker and exposes a small typed RPC API to the main thread (`open`, `getSummary`, `getObsColumn`, `getSpatial`, `getGeneVector`, `getVarNames`, `close`). Transfer typed arrays with `postMessage(..., [buffer])`, never copy.

### 5.1 File layout to support
Root groups: `X`, `obs`, `var`, `obsm`, `obsp`, `varm`, `varp`, `uns`, `layers`, `raw`. Any may be absent (`X` can be missing entirely). Read `encoding-type` / `encoding-version` attributes when present but tolerate their absence.

**Dataframes (`obs`, `var`)** — a group with attributes `_index` (name of the index dataset) and `column-order`. Column encodings:
- numeric dataset (int/uint/float of any width; convert to `Float32Array`/`Float64Array`/`Int32Array` as appropriate)
- string array dataset (variable-length or fixed-length strings)
- boolean dataset (h5py stores as an enum; h5wasm decodes it — verify)
- **categorical (anndata ≥ 0.8)**: a group with `codes` (int dataset, `-1` = missing), `categories` (string or numeric dataset), attribute `ordered`
- **categorical (legacy anndata < 0.8)**: an int `codes` dataset whose `categories` attribute is an object reference to `__categories/<column>`; also handle the case where `__categories/<column>` exists by name
- `nullable-integer` / `nullable-boolean`: group with `values` + `mask`
- Treat any column you cannot decode as "unsupported" and list it as such, without failing the load.

**`obsm`** — 2D datasets of shape `(n_obs, k)`, or occasionally a dataframe group. Row-major (C order) is the default; verify against the dataset's shape rather than assuming.

**`X` / `layers/*` / `raw/X`** — either a dense dataset `(n_obs, n_vars)` or a sparse group with attribute `encoding-type` = `csr_matrix` or `csc_matrix`, attribute `shape`, and datasets `data`, `indices`, `indptr`. Also handle the legacy `h5sparse_format` / `h5sparse_shape` attributes.

**Gene names** — default to the `var` index. Also detect common alternative columns (`gene_symbols`, `gene_symbol`, `feature_name`, `symbol`) and let the user switch which column is used for search/display. Handle duplicate names (append a suffix in the UI, keep the true column index internally).

**Categorical colors** — `uns/<obs_column>_colors` is a string array of hex colors aligned with `categories`. Use it when its length matches; otherwise fall back to a generated palette.

### 5.2 Spatial coordinate auto-detection (Squidpy conventions first)
1. **Native 3D**: stop at the first `obsm` key with 3 columns, in this order: `spatial3d` (Squidpy's key for stacked 3D data, e.g. its MERFISH tutorial), `spatial_3d`, `X_spatial_3d`, `spatial` (Squidpy's canonical key; usually 2D but may be 3D), `X_spatial`, then any `obsm` key containing "spatial" or "xyz".
2. **2D + explicit z**: if the best key has 2 columns, look for a numeric z in `obs`: `z`, `Z`, `z_coord`, `z_um`, `depth`, `Bregma` (MERFISH slice position, may be negative).
3. **2D + library/section stacking** (the primary case): find the `library_key` column — a categorical/string `obs` column whose categories match the keys of `uns/spatial` when that group exists; otherwise the first of `library_id`, `library`, `sample`, `sample_id`, `section`, `slice`, `slide`, `fov`, `z_index`, `batch`. Order sections by `uns/spatial` key order if available, else natural sort of the category names (if names embed numbers such as `S1…S12` or `Bregma_-0.29`, sort numerically). Build a **section model** — `{ id, name, ordinal, n_cells, hasImage, spotDiameter, bbox }` per section — that the Filter, Appearance, Info, and image-overlay features all consume.
4. **Nothing found**: render with z = 0 and show a notice ("2D dataset — pick a z source in Coordinates").

**Section layout modes** (Coordinates panel, must-have, all applied in the vertex shader from per-section uniforms so switching is instant):
- **Stack** (default): z = ordinal × spacing, spacing defaulting to 15% of the larger XY extent. Sections from different slides share one XY frame per platform (Visium pixel space, Xenium/CosMx microns), so stacking is a sensible default even though sections are not registered to each other.
- **Stack, normalized**: same, but each section's XY is centered on its own bounding-box center first (use this when slides have different capture-area offsets).
- **Tile**: sections laid out side-by-side in a grid on the z = 0 plane (columns = ceil(sqrt(n)), gap adjustable) and the camera switched to top-down orthographic — the multi-panel view `sq.pl.spatial_scatter(..., library_key=...)` gives, but interactive.
- **Single**: show one section at a time (drives the same section stepper as the Filter panel), top-down orthographic by default.
Per-section manual alignment (XY offset, rotation, flip) is a nice-to-have (§7.3); leave hooks for it in the section model.

Units are not standardized (Visium = full-resolution image pixels, Vizgen/Xenium = microns, CosMx = global pixels). The viewer is unit-agnostic but must show the raw extent per axis in the Info panel and never assume equal XY/Z units — the MERFISH tutorial explicitly warns that z is often in a different unit from XY, so the z-scale slider in Coordinates matters.

Regardless of detection, the UI must expose a **Coordinates** panel where the user can override the X, Y, Z sources from any `obsm` column or numeric `obs` column, choose the library/section column, set section spacing and a z-scale multiplier, and apply a "swap Y/Z" toggle and per-axis flips. Image-space coordinates (Visium) have y pointing down; provide a "flip Y" that defaults on when `uns/spatial/*/images` exists so tissue appears upright.

Center coordinates and scale to a unit cube in **float64 on the worker** before casting to `Float32Array` for the GPU — raw micron coordinates in the 10⁴–10⁶ range cause visible float32 jitter otherwise. Preserve aspect ratio.

### 5.3 Gene expression extraction (one column of `X` at a time)
- **CSC**: read `indptr[j]`, `indptr[j+1]` via slicing, then slice `data` and `indices` over that range. This is cheap — treat CSC as the preferred on-disk layout and say so in the docs.
- **Dense**: use h5wasm dataset slicing to read column `j` (`[[0, n_obs], [j, j+1]]`). Acceptable for moderate matrices.
- **CSR**: a single column requires scanning all of `indices`. Do it in chunks inside the worker with progress reporting, never load the full `indices`/`data` at once. If `nnz` exceeds a threshold (start with 50 M), show a warning that expression coloring will be slow and recommend `scripts/prepare_h5ad.py --csc`. Cache the sparse column results.
- Support choosing the matrix source: `X`, any `layers/<name>`, or `raw/X` (if `raw` exists, its `var` may differ — map gene names accordingly).
- Keep an LRU cache of the last ~20 gene vectors in the main thread as `Float32Array`.
- Provide a `log1p` toggle and percentile-based range clipping (computed on the worker from the returned vector).

### 5.4 Compression filters
gzip and shuffle work out of the box. If opening a dataset fails with a filter error, lazily import `h5wasm-plugins`, install the plugins, and retry once. If it still fails, surface a specific message naming the filter and suggesting `prepare_h5ad.py --compression gzip`.

### 5.5 Partial reading discipline
Read only what is needed, when it is needed: on open, read the structure (keys, shapes, dtypes, attributes), `n_obs`, `n_vars`, the spatial coordinates, `var` names, and the `obs` column list with dtypes and category counts. Load individual `obs` columns and gene vectors on demand. Never read `X` wholesale, and never read `uns` wholesale (Squidpy files can carry large analysis results there).

### 5.6 Squidpy-specific structures to recognize
Detect these on open, list them in the dataset summary, and load their contents only when a feature needs them:

- **`uns/spatial/<library_id>/`** — one group per section/slide.
  - `images/hires`, `images/lowres` (Visium; `uint8` or `float` in [0, 1], shape `(H, W, 3)` or `(H, W, 4)`; CosMx files may instead have per-FOV `images/hires` and `images/segmentation`). These feed the **tissue image overlay (§7.2 item 2, must-have)**. Read one image at a time in the worker, convert to RGBA `uint8`, downscale so the longest side is ≤ 2048 px (≤ 1024 px when there are more than 8 sections) and keep total texture memory under ~256 MB, transfer as an `ImageBitmap`/typed array, and dispose on dataset switch. Prefer `lowres` automatically when there are many sections or the device reports low GPU memory, and let the user pick the resolution.
  - `scalefactors/` — `tissue_hires_scalef`, `tissue_lowres_scalef`, `spot_diameter_fullres`, `fiducial_diameter_fullres`. `obsm["spatial"]` is in full-resolution pixel space; the hires image spans `(W / tissue_hires_scalef) × (H / tissue_hires_scalef)` of that space with its origin at the top-left (y down). `spot_diameter_fullres` gives the true spot size in coordinate units. Vizgen files may carry `scalefactors/transformation_matrix` and a `metadata` group instead; tolerate arbitrary extra keys.
  - Values in `uns` are stored with the same encodings as `obs` columns (scalars as 0-d datasets, dicts as groups, strings as vlen strings); reuse the dataframe decoders.
- **`obsp/spatial_connectivities`** (binary adjacency) and **`obsp/spatial_distances`** (weighted), both `(n_obs, n_obs)` CSR written by `sq.gr.spatial_neighbors`; `uns/spatial_neighbors/params` records `n_neighbors`, `radius`, `coord_type`, `transform`. A non-default `key_added` produces `obsp/<key>_connectivities`; detect any `obsp` key ending in `_connectivities`. Read `indptr`/`indices` in chunks and emit line-segment vertex pairs for the graph overlay (§7.3); take only `i < j` to avoid duplicate edges; cap at a configurable number of edges (default 1 M) with uniform subsampling beyond that.
- **Analysis results in `uns`** (read lazily, only the small ones): `moranI` (a dataframe indexed by gene with columns `I`, `pval_norm`, …) → offer "top spatially variable genes" in the gene picker; `<cluster_key>_nhood_enrichment/zscore`, `<cluster_key>_co_occurrence`, `<cluster_key>_ripley_*`, `<cluster_key>_centrality_scores` → list as present in the summary, do not visualize (out of scope).
- **`obs` columns written by Squidpy/Scanpy** that deserve default treatment: `leiden`/`louvain`/`cluster*`/`cell_type`/`celltype` (categorical, good default color-by, in that priority), `total_counts`, `n_genes_by_counts`, `pct_counts_mt`, `in_tissue` (Visium; offer a filter to hide `in_tissue == 0` spots), `array_row`/`array_col` (Visium grid indices — never mistake these for spatial coordinates).

## 6. Rendering

- Single `THREE.Points` with a `BufferGeometry`. Attributes: `position` (Float32 ×3, the section's native 2D XY plus z = 0 for stacked data), `section` (Uint16 ordinal, 0 for native-3D data), `scalar` (Float32, the current continuous value or NaN), `code` (Uint16/Float32, current categorical code), `pointId` (for picking), `visible` (Uint8 0/1 for user filters/subsampling).
- Custom `ShaderMaterial`:
  - Color from a 256-entry **colormap `DataTexture`** sampled with `(scalar - vmin) / (vmax - vmin)`, or from a **palette `DataTexture`** indexed by `code`. Changing colormap, range, or palette therefore only updates a texture/uniform — no per-point CPU work, no re-upload.
  - Category visibility as a small mask texture (or uniform array) indexed by `code` so legend toggles are O(1).
  - **Per-section transform table** (a small `DataTexture` or uniform array indexed by `section`: XY offset, z, visibility, optional rotation/flip) so switching between stack / normalized / tile / single layouts, changing spacing, or toggling a section never re-uploads positions.
  - Uniforms for point size (screen pixels, perspective-attenuation mode, or world-units "true spot size"), opacity, NaN color, per-axis clip bounds, z-range, and a "section explode" factor `z' = zc + (z - zc) * factor`.
  - Round sprites with soft edges via `gl_PointCoord`; square option. Discard fragments that fail visibility/clip tests.
- **Tissue image planes**: one `PlaneGeometry` + `MeshBasicMaterial` (transparent, `depthWrite: false`, `toneMapped: false`, `SRGBColorSpace`) per section, positioned by the same per-section transform table so it always follows its points in every layout mode. Extent and origin come from §5.6 (`W / tissue_hires_scalef` × `H / tissue_hires_scalef`, top-left origin, y flipped), placed a small epsilon below the section's points and rendered before them (`renderOrder`) so spots always draw on top. Hidden sections hide their plane.
- Camera: perspective by default with an orthographic toggle. `OrbitControls` (rotate / pan / zoom, touch-friendly), damping on, "Reset view", preset views (top / front / side / isometric), and a "turntable" auto-rotate toggle. Tile and Single layouts switch to top-down orthographic and frame the content automatically; leaving them restores the previous camera.
- Helpers: axes triad in a corner, bounding box, optional grid; all toggleable.
- **Picking**: GPU picking — render point IDs as colors to a 1×1 render target at the cursor position (`camera.setViewOffset` or scissor), read one pixel, decode the ID. Throttle to ~30 Hz on mouse move. Do not use `Raycaster` against `Points` for large clouds.
- Background: dark by default, light option; text and axis colors adapt.
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, render on demand (only when something changed), handle `resize` and `webglcontextlost`/`restored`.
- Dispose geometry, material, textures, and render targets on dataset switch. Verify with `renderer.info` that memory returns to baseline.

## 7. UI and features

### 7.1 Layout
Full-viewport canvas with a collapsible left sidebar (tabs or accordion sections: **Dataset**, **Sections**, **Color**, **Filter**, **Coordinates**, **Appearance**, **Info**), a slim top bar (SPV wordmark, dataset name, point count, current section name when in Single mode, screenshot, share link, help), and a floating tooltip near the cursor. Responsive: sidebar becomes a bottom sheet under ~800 px width. Keyboard shortcuts: `R` reset view, `H` toggle sidebar, `F` toggle fullscreen, `S` screenshot, `1/2/3` preset views, `←/→` previous/next section, `I` toggle tissue images, `L` cycle layout mode, `Esc` clear selection.

### 7.2 Must-have features
1. **Dataset**: dropdown from the manifest (with size and description), Open URL, Open local file / drag-and-drop, loading progress with stages (download → open → coordinates → ready) and a cancel button. Dataset summary: n_obs, n_vars, `X` encoding and nnz, `obsm` keys with shapes, `obs` columns with dtype and category counts, `layers`, whether `raw` exists, the detected coordinate source and library column, the sections listed in `uns/spatial` (with image availability and `spot_diameter_fullres`), and which spatial graphs / Squidpy results are present.
2. **Sections** (shown whenever the dataset has more than one section, or a `Bregma`-style discrete z):
   - Layout mode switch: Stack / Stack normalized / Tile / Single (§5.2), plus spacing, tile gap, and explode sliders.
   - Section list with name, cell count, image indicator, checkbox (show/hide), and a solo button; "show all / hide all". Virtualize above ~50 sections (CosMx FOVs).
   - **Section stepper**: previous / next / play with speed control; in Stack mode it highlights the current section (others dimmed via opacity uniform), in Single mode it swaps the visible section. Current section name shown in the top bar.
   - **Tissue image overlay**: master toggle, opacity slider, resolution choice (`hires` / `lowres` / auto), per-section on/off inherited from the section checkbox, a "grayscale" toggle (helps colored spots read against H&E), and a loading indicator per image. Show a note when a section has no image or lacks the scale factors needed to place it (CosMx/Vizgen layouts without `tissue_hires_scalef` are listed as "image present, placement unknown").
   - Section-level info on hover over the list entry: bbox extent in coordinate units, `spot_diameter_fullres`, image size.
3. **Color by**
   - *Categorical `obs`*: dropdown → legend with swatch, category name, and cell count; click to toggle, Shift-click to solo, buttons for show all / hide all / invert; search box when there are more than ~30 categories; virtualize the legend list above ~200 categories. Palette: `uns/*_colors` if valid, else a color-blind-friendly qualitative palette for ≤ 10 / ≤ 20 categories and a generated maximally distinct palette beyond that.
   - *Continuous `obs`*: numeric columns → colormap + range controls.
   - *Gene expression*: search box with autocomplete over `var` names (case-insensitive prefix + substring, debounced, works fast with 30k+ genes), matrix-source selector (`X` / layers / raw), `log1p` toggle.
   - Continuous controls shared by the last two: colormap picker (viridis, plasma, inferno, magma, cividis, turbo, coolwarm, greys, and a reversed toggle), range by percentile (dual slider, default 0–99.5) or explicit min/max, a colorbar with tick labels, and a NaN/zero color choice.
4. **Filter**
   - Z-range dual slider (native-3D data) — for sectioned data this is replaced by the Sections panel controls above.
   - `in_tissue` quick filter when that Visium column exists (default: show only `in_tissue == 1`, with a toggle).
   - X/Y clip-plane dual sliders (applied in each section's native XY frame so they work in Tile mode too).
   - Random subsampling to N points (for performance on huge files), applied via the `visible` attribute.
   - Category filters set from the legend are reflected here.
5. **Appearance**: point size, opacity, sprite shape, perspective attenuation toggle, background, axes/bounding-box/grid toggles, orthographic toggle. When `spot_diameter_fullres` is available, offer a **"true spot size"** mode that renders each spot at its physical diameter in coordinate units (world-space point size), the way `sq.pl.spatial_scatter` does; make it the default when tissue images are shown so spots line up with the H&E.
6. **Hover / select**: tooltip shows cell index / `obs` index name, the section name, the value that drives the current color, and up to six user-chosen `obs` fields (multi-select in Info panel; columns are fetched lazily from the worker and cached). Click pins the tooltip and highlights the point (bigger, outlined); `Esc` clears.
7. **Export**: PNG screenshot at 1× or 2× resolution with transparent or current background; **Copy share link** (see §8). When the dataset is a local file, the share link encodes view state only and the UI says the recipient must open the same file.
8. **Robust loading and errors**: WebGL unavailable → explanatory page; invalid/unsupported file, no spatial coordinates found (offer the Coordinates panel), CORS failure, unsupported filter, out-of-memory guesses, image decode failure (fall back to points only) — all with actionable messages, never a blank screen or console-only error.
9. **Help**: a short in-app modal with controls, shortcuts, supported file features, and the privacy note.

### 7.3 Nice-to-have (only after every must-have passes acceptance; implement in this order)
1. **Manual section alignment**: per-section XY offset, rotation, and flip controls (drag handles in Single/Tile mode or numeric inputs), stored in the per-section transform table and serialized in the share link — for roughly registering serial sections by eye.
2. **Spatial graph overlay** from `obsp/*_connectivities` as a single `LineSegments` object (edge color, opacity, and the edge cap from §5.6 adjustable; edges respect the same section/clip/category filters as points by sharing the visibility logic — hide an edge if either endpoint is hidden; edges never cross sections when the graph was built with `library_key`).
3. **"Top spatially variable genes"** list in the gene picker when `uns/moranI` exists (sorted by `I`, show the value; clicking colors by that gene).
4. **Section crossfade**: in Single mode, animate between consecutive sections with a short opacity blend so serial sections read as a flip-book.
5. Two-gene blend coloring (gene A → one channel, gene B → another).
6. Lasso / box selection in screen space with "export selected cell IDs as CSV/TSV" (include the section name column).
7. Small histogram of the current continuous variable next to the colorbar, with draggable range handles.

## 8. URL state (shareable views)

Serialize state into the URL hash (hash, not query string, so navigation never reloads): dataset `id` or `url`, coordinate source overrides, section column, layout mode + spacing/gap/explode, hidden sections and current section (compact encoding), image overlay on/off + opacity + resolution + grayscale, color mode + key (+ matrix source, log1p, colormap, reversed, range mode and values), hidden categories (compact encoding), filters (z-range, clips, `in_tissue`, subsample), appearance (point size / true-spot-size, opacity, background, projection), and camera (position, target, up, zoom for ortho). Debounce updates. Parse on load, apply after the dataset is ready, and ignore unknown keys gracefully. Keep the encoding compact and versioned (`v=1`).

## 9. Performance targets (measure, don't assume)

- 500k points: ≥ 55 fps orbiting on a 2022-class laptop with integrated graphics; 2 M points still interactive (≥ 20 fps).
- Time-to-first-render for `data/demo.h5ad` over a fast connection: points visible within 3 s plus download time (report both; if the file is tens of MB, lazy range-request loading in §4.3 is what makes this achievable — measure with and without it), and always before any tissue image finishes loading (images stream in afterwards, one by one, without blocking interaction).
- Switching layout mode (stack ↔ tile ↔ single), spacing, or stepping sections: no main-thread stall > 16 ms and no position re-upload (per-section transform table only).
- Tissue images: all sections of `data/demo.h5ad` at the chosen resolution decoded and uploaded in < 4 s total (state the section count and image sizes when reporting); stepping sections in Single mode with images on stays ≥ 55 fps.
- Changing colormap, range, point size, category visibility, or filters: no main-thread stall > 16 ms (they must be texture/uniform updates).
- Switching a gene on CSC or dense data of 500k × 30k: < 1 s after the click.
- Main thread never blocks on HDF5 I/O; all parsing is in the worker with progress messages.
- Report actual numbers in the README.

## 10. Edge cases to handle explicitly

Missing `X`; `X` stored as integers; `X` as float64 (downcast to float32 for the GPU); `n_obs` mismatch between `obsm` and `obs` (error clearly); NaN/inf in coordinates (drop those points and report the count); categorical with `-1` codes (missing category → "NA" legend entry); category count > 65535 (fall back to a Float32 code attribute); duplicate gene names; zero-variance gene (vmin == vmax → avoid division by zero, show a flat color); very large `uns` (never read it wholesale, only the keys named in §5.6); files that are HDF5 but not AnnData; `.h5ad` written by R (`anndataR`/`zellkonverter`), Seurat converters, and older Scanpy versions; obs index stored as bytes; datasets with chunked/compressed layouts where column slicing touches many chunks (still correct, just slower — show progress).

Squidpy-specific: `uns/spatial` with hundreds of entries (CosMx, one per FOV — do not pre-read images, and virtualize the section list); a `library_key` column whose categories do not match `uns/spatial` keys (fall back to category order, warn in the summary); sections with different XY frames (offer per-section normalization, §5.2 step 3); `obsm["spatial"]` stored as float64 pixel coordinates in the 10⁴ range (center in float64 first, §5.2); images stored as float in [0, 1] vs `uint8` vs RGBA; `spot_diameter_fullres` present for only some sections; `obsp` graph computed with a non-default `key_added`; `spatial_connectivities` stored as CSC or dense by third-party tools (support CSR primarily, tolerate CSC, refuse dense over 10⁸ elements with a message); files where `obsm["spatial"]` exists but the user's real 3D coordinates live in a differently named key (the Coordinates panel must make that a two-click fix).
